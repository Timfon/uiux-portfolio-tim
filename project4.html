Introduction:

The project aims to implement a recursive and iterative DNS resolver in Python. Our tool is similar in functionality to the "dig" command, but with more verbose output that can allow the user to see the DNS resolution process in detail. The project successfully implements a DNS resolver capable of performing full iterative queries, recursive lookups, and single-step queries for both root servers and specific nameservers.

Design/Implementation:

The resolver is implemented in Python using the dnspython library and utilizes three main query types: single-step queries (single_step_query), full iterative resolution (full_iterative_query), and recursive resolution (recursive_query). Additionally, some nameserver extraction logic was needed to get the next nameserver's IP from the response. The DNS program is wrapped in a user-friendly command-line interface implementing a REPL that accepts dig-style commands, and includes query timing management to track the DNS resolver's performance.

For single-step queries, the program performs a single DNS query to a specified server. For both recursive and iterative queries, our program starts from a default root server (198.41.0.4) or the server specified by the user. The program shows each step of the resolution process and returns the final answer or fails if resolution is impossible.

REPL query formats

dig Command Usage:
  • dig <domain>
    • Full recursive query from default root server
  • dig <domain> -i
    • Full iterative query from default root server
  • dig <domain> @<server> -r
    • Full recursive query from specific server
  • dig <domain> @<server> -i
    • Full iterative query from specific server
  • dig <domain> @<server>
    • Single step query to specific server

Caching Example:

The program clearly implements a fully functional DNS resolver, with single-step, iterative, and recursive queries. As seen in the results, the resolver handles DNS referrals and nameserver extraction in a command-line interface. We also implement a basic caching system that caches found answers within a hashmap, which also logs an object representing the cache time of the entry. We use this to decrement the TTL of the cached entry. Rather than constantly checking whether an item is cached via some sort of concurrency model, we check the TTL every cache hit - if the TTL is expired perform whatever operation is necessary to obtain the answer and cache it again. As seen in the screenshot above, this improves our performance significantly.

Some challenges that came up was name server resolution, which required careful handling of cases where the additional section was empty or when glue records were absent. Some other challenges that came up was the usage of the server 8.8.8.8, which seemed to automatically resolve the user's domain in one step, without showing the full path in the output.

Conclusion

Our Python DNS resolver provides a way for users to clearly see the DNS resolution process in detail– the iterative implementation especially helped visualize how the DNS hierarchy works in practice. Some potential improvements could be to add support for more DNS record types. Some other nice features to have would be IPv6 support, or a user interface that can visualize the path of the DNS query. Overall, the program clearly demonstrates the mechanisms of iterative and recursive DNS queries, and serves as a useful tool for understanding DNS infrastructure. The project successfully achieves its goal of demonstrating the DNS resolution process while providing a good starting point for future improvements and extensions.
